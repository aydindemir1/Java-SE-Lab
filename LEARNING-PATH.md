# Her projede seviye standardı

## Junior
- Syntax
- temel API
- doğru kullanım
- küçük egzersizler

## Mid
- idiomatic Java
- alternatif API'ler
- seçim kriterleri
- yaygın hatalar
- test edilebilirlik

## Senior
- API contracts
- maintainability
- edge cases
- concurrency/performance etkileri
- production-grade error handling

## Expert
- implementation details
- runtime/JVM etkileri
- profiling
- düşük seviyeli trade-off'lar

## Staff / Principal / Architect
- Java odaklı teknik karar
- ölçek, performans, memory ve operability etkileri
- API/library tasarımı
- compatibility
- farklı seçeneklerin neden seçildiğinin gerekçelendirilmesi

> Staff/Principal/Architect seviyesi başka teknolojiler eklemek değildir; Java kararlarının daha geniş teknik sonuçlarını görebilmektir.

# Çalışma kuralı

Bir ana proje tamamlanmış sayılmadan:
- teori yazılmalı,
- temel ve ileri örnekler çalışmalı,
- gerçek hayat senaryoları bulunmalı,
- pitfalls açıklanmalı,
- testler çalışmalı,
- exercises eklenmeli,
- seviye matrisi tamamlanmalı,
- ilgili JVM/runtime etkileri gerekiyorsa açıklanmalıdır.
